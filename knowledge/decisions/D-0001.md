# D-0001 — The Another Gun Mod bridge is an optional subproject of this repo

**Decision**: The code that binds Another Gun Mod to the protocol lives at
`bridges/agm/`, a Gradle subproject building its own mod jar
(`armedpillagers-agm`, mod id `armedpillagers_agm`). `settings.gradle`
includes it only when the vendored gun-mod jar is present in
`bridges/agm/libs/`, and says what it skipped otherwise. The bridge depends
on the protocol and the gun mod, never on this mod.

**Why**: Bridges are owned by whoever needs them, and today that is this mod;
a repo per bridge was the first plan ("three repos") and was reversed by the
author on the observation that each mod repo should carry its own bridges.
A subproject keeps that ownership without the costs of the alternatives: the
main jar never references `com.f708`, so a pack without the gun mod never
loads a class that would fail to link; the main mod builds and passes every
test from a clean clone with no third-party jar; and the bridge serving the
protocol rather than this consumer means any future mob-arming mod gets the
gun mod for free.

Licensing is unaffected by location. The bridge is AGPL wherever it lives and
links the gun mod's public API without redistributing it — exactly what this
mod did before the split.

**Alternatives rejected**: *A separate `minecraft-armed-pillagers-agm` repo* —
a third repo to version in lockstep, for code that is 200 lines and changes
with this mod. *Inside the main jar with the gun mod optional* — every class
touching `com.f708` must then be kept off every code path when the mod is
absent, which is a runtime discipline instead of a compile-time guarantee.
*Reflection or mixins into the gun mod* — silent breakage on update instead
of a compile error.

**Follow-ups**: A second bridge (`bridges/<mod>/`) follows the same shape:
`gradle.properties` overriding `mod_id`, a `libs/README.txt`, a conditional
`include`.
