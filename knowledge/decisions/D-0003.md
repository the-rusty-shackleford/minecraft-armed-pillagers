# D-0003 — The gametests are a mod of their own

**Decision**: The `gametest` source set is registered with ModDevGradle as a
second mod, `armedpillagers_gametest`, with its own `neoforge.mods.toml` and
its own datapack, rather than as another source set of the main mod. It is
loaded by the gametest run only; the client and server runs (and so the
mcfunction harness) host the shipped mods alone.

**Why**: A mod with several resource roots cannot supply the same file from
two of them — the first root wins — and a data map's file path is fixed per
map (`data/rangedweapons/data_maps/item/weapons.json` for every contributor).
The tests need their own profiles and loadouts for vanilla items beside the
ones this jar ships for Another Gun Mod, and as a second source set of the
same mod theirs would have been shadowed. As their own mod they are a second
pack, merged by the loader like any datapack. That also makes them exercise
the mod from outside, exactly as a pack author would, and lets the gate pass
on a clean clone with no gun mod anywhere: a pillager handed a profiled stick
shoots it on the fallback tier.

**Alternatives rejected**: *A world datapack copied into the gametest world*
— the gametest server's world is created by the framework; injecting a pack
means reaching into its directory layout. *Tests as a source set of the main
mod with data under another namespace* — data-map file paths are not
per-namespace, so there is no other path. *No test data; test only the
shipped guns* — the gate then needs the vendored jar, which a clean clone
does not have.

**Follow-ups**: The protocol repo's gametests stay a source set of the
protocol mod; its main ships no data files, so nothing is shadowed there.
